# Internal Onboarding

This site is the internal developer outline for the Splunk Operator for Kubernetes (SOK). It is intended to connect public SOK documentation, internal Kraken-based setup, build and test workflows, troubleshooting paths, and contribution expectations.

## How to Reach the SOK Team

The SOK team has consolidated our Slack presence to make it easier to get help, share requests, and stay informed.

Use these channels:
- [#sok-platform](https://splunk.enterprise.slack.com/archives/C0ASGTUEA2W) — for new feature requests, questions about plans, and alignment on the work in flight (following the [posting etiquette](https://splunk.enterprise.slack.com/docs/T024FQ3UW/F0AK0J3TESV) as in [#platform-arch](https://splunk.enterprise.slack.com/archives/C069YH42R3P))
- [#sok-support](https://splunk.enterprise.slack.com/archives/CEJ9W5QPL) (formerly #splunk-operator) — for questions about **released** SOK versions, including bug reports and customer issue discussions
- [#sok-announcements](https://splunk.enterprise.slack.com/archives/C0ASH3EH97U) — observe for announcements about upcoming plans and released features

Please note:
- Commitments and agreements need to be tracked in #sok-platform — private conversations won't be treated as binding

## Get Access to the SOK Project in GitLab
Please submit an access request using the steps below:
1. Open http://go/fast
2. Click **Access Request**
3. Select **GitLab Invite Group to Project Request**
4. Enter the required details, including the GitLab group that needs access
5. Submit the request

Once submitted, an admin will review the request and add the provided group to the project.

**Tip:** Please make sure the GitLab group name is correct before submitting to avoid delays.
